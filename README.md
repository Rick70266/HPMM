# 戰情室 MVP · War Room MVP

版本 20261115-1 · 檔案上傳版（商業決策＋促銷＋異常）

## 這是什麼

公司目前沒有報表工具，每次想看數字都要人工從 RTMM / POS / ERP 撈資料再加工。這個戰情室先不接資料庫，**只吃你已經撈得出來的 Excel / CSV**，上傳後自動算出總表、排名、促銷業績與例外清單。

對照 RTMM 訓練文件（2016/07/01）的八大功能，本版先做最能證明價值的三個模組：

- **首頁 · 商業決策**：月至今 MTD / 年至今 YTD 切換、營業額、成長率 YoY、達成率、毛利率、來客數、每日趨勢、店別排行（排序後排名從第 1 名重算）、處／課排行、商品 TOP 10
- **促銷管理**：各檔期促銷業績、促銷佔比、促銷商品 TOP 5、店／課促銷業績、檔期重疊檢核（同一貨號檔期重疊時，依 RTMM 規則以最低價為生效檔期，列出需人工確認的清單）
- **異常管理**：例外清單，含店／課業績大跌（預設較去年同期跌超過 10%，可調門檻）、毛利率偏低（<10%）、呆滯品（最後異動 >90 天）、滯銷品（31~90 天），可下載 CSV

## 檔案結構

```
app.py                    Streamlit 主程式

sample_data/              示範資料（虛構數字，僅供測試）

  targets.csv             目標表（每月每店）

  promo.csv               促銷檔期表（刻意放一組重疊檔期示範檢核）

```

## 上傳檔案格式

欄位名稱可用中文或英文，程式會自動對照。至少要有一檔才能跑：

| 檔案 | 必填 | 主要欄位 |
|---|---|---|
| 銷售日報表 | 必填 | 日期、店別、處別、課別、貨號、商品名稱、銷售額、銷售量、毛利額、來客數 |
| 目標表 | 選填 | 期間（YYYY-MM）、店別、目標金額；缺了達成率不顯示 |
| 商品主檔 | 選填 | 貨號、商品名稱、處別、課別、廠商名稱、廠商編號、商品狀態、售價、成本 |
| 促銷檔期表 | 選填 | 檔期代號、檔期名稱、起日、迄日、貨號、促銷價、促銷類別（G 全區域 / S 採購建議 / L 分店建議） |
| 庫存表 | 選填 | 貨號、商品名稱、店別、庫存量、庫存金額、最後異動日；缺了呆滯／滯銷不顯示 |

CSV 請用 UTF-8，Excel 用 .xlsx。RTMM 匯出的 Excel 若是 Big5 編碼，程式會自動嘗試解碼。

## 本機測試

```bash
cd war-room-mvp
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/streamlit run app.py
# 開 http://localhost:8501
# 左側預設勾「使用示範資料」，先看三頁是否正常；關掉後再上傳自己的檔案測試
```

## 上傳 GitHub ＋ Streamlit 部署

1. 在 GitHub 新建一個 **私人（Private）** repo，把本資料夾裡面的檔案推到根目錄。
2. 到 Streamlit Cloud → New app → 選該 repo、branch（`main`）、Main file path 填 `app.py` → Deploy。
3. 之後改 `app.py` 再推上 GitHub，網頁會自動更新。左側欄有版本標記「版本 20261115-1」，先看版本再比數字，可分辨是不是舊版。

## ⚠️ 資安提醒（重要）

- **不要把真實公司資料推到公開 repo，也不要把真實資料上傳到公開 Streamlit Cloud 試用。** 示範資料是虛構的，可以公開測試；真實資料請先在本機或公司內網跑。
- 正式上線前請先問 IT：資料庫品牌與唯讀帳號、檔案能不能放內網共用資料夾、使用者權限要切到店別／課別嗎。
- 上傳的檔案在 Streamlit 執行期間只存在記憶體，關掉或重整就消失，不會自動存檔；要留底請用頁面上的「下載 CSV」。

## 下一階段（等 MVP 被主管認可後再做）

1. 內部部署：改跑公司內網伺服器或共用電腦，加上帳號密碼，不再經過外部雲端。
2. 固定範本：把 RTMM 每次匯出的欄位順序固定下來，減少每次上傳要對欄位的時間。
3. 資料庫直連：確認資料庫品牌與唯讀權限後，加一層唯讀查詢，改成每天自動更新，不再手動上傳。
4. 擴充模組：人力資源（人效）、商品管理（新品追蹤、上架率）、季節區、價格管理（改價建議）。
